## [Unreleased]

### Added

- **Stream-based transcript telemetry**:
  - `StreamWorker` processes validated checkpoint notifications immediately and
    performs lower-priority agent discovery sweeps at startup, every 30 minutes,
    and after eligible commit or push events
  - Schema-v4 stream cursors and watermarks are stored in
    `~/.git-ai/internal/transcripts-db`; raw transcript content remains in the
    agent-owned source files
  - Agent-specific bounded readers live under `src/operations/streams/` and
    support per-stream watermark strategies
  - Transcript and OTEL events carry session and trace attributes, with
    secret-shaped JSON values redacted before local persistence
- **Durable metrics history and delivery queue**:
  - Schema-v5 events are stored in `~/.git-ai/internal/metrics-db` with cached
    query metadata and row-level delivery state
  - Metrics upload requires the opt-in `telemetry` setting plus an API key or
    login; queued session events are rechecked against current repository
    eligibility before delivery

### Changed

- Transcript discovery uses checkpoint notifications and sweep-based discovery,
  replacing the abandoned per-session one-second polling design.
- `internal_db` remains the schema-v3 store for the legacy prompt/CAS queue; it
  is not automatically migrated into the streams database.

### Technical Details

- **Architecture**: `StreamWorker`, stream adapters, schema-v4 cursor storage,
  `DaemonTelemetryWorker`, and schema-v5 metric storage
- **Processing model**: Immediate checkpoint work plus cooldown-coalesced initial,
  periodic, post-commit, and post-push sweeps
- **Durability**: Watermarks advance after bounded batches are persisted locally;
  metric delivery uses bounded row-level retry and retained local history

The current runtime contract is
`docs/contracts/telemetry-streams-summary.md`. Dated documents under
`docs/decisions/` are historical design records.
